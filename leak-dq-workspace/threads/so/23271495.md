## Question

C++ has several functions to acquire dynamic storage, most of which differ in some fundamental way. Several more are usually added by the OS.

Two of these are of special interest due to their portability and similarity: `malloc` and `::operator new`.

Are there any differences (w.r.t. the standard and implementation) between the global `void* operator new(size_t, ::std::nothrow&)` and `void* malloc(size_t)`?

Since there seems to be some confusion what I am talking about, consider the following two calls:

```
void* p = ::std::malloc(10);
void* q = ::operator new(10, ::std::nothrow);

```

The obvious and trivial difference is how to deallocate the memory:

```
::std::free(p);
::operator delete(q);

```

Note: This question is not a duplicate of e.g. [What is the difference between new/delete and malloc/free?](https://stackoverflow.com/questions/240212/what-is-the-difference-between-new-delete-and-malloc-free) since it talks about using the *global* `operator new` that does not actually perform any ctor calls.

There are two differences I can think of:

1. 

Which function you must use to deallocate the memory, `operator delete` vs. `free()`.

1. 

A C++ program can legally provide its own version of `::operator new` and that version is guaranteed to be called by `new` expressions. It's not possible to override `malloc` with your own version.

The main differences, aside from syntax and `free` vs. `delete`, are

1. you can portably [replace](http://en.cppreference.com/w/cpp/memory/new/operator_new#Global_replacements) `::operator new`;

1. `malloc` comes with `realloc`, for which `new` has no equivalent;

1. `new` has the concept of a [`new_handler`](http://en.cppreference.com/w/cpp/memory/new/new_handler), for which there is no `malloc` equivalent.

(Replacing `malloc` opens up a [can of worms](https://web.archive.org/web/20170204072041/https://www.iecc.com/linker/linker09.html). It can be done, but not portably, because it requires knowledge of the linker.)
