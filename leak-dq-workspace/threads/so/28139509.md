`SetSoundProducer` simply reassigns what `Uppgift1::t` points to without considering what it used to point to. That's a definite memory leak. You should use a `std::unique_ptr` and call its `reset()` method. Also, `SoundProducer` needs a virtual destructor because otherwise you have undefined behavior.

## Answer 28139618

responder · Deduplicator · 2015-01-25T18:01:05Z · score 0 · https://stackoverflow.com/a/28139618

`Uppgift1.SetSoundProducer` takes ownership of the passed `SoundProducer`, aside from not doing quite that:

1. It will `delete` the last one set on destruction.

1. But **it won't `delete` the previous one** on setting a new one.

Also, the **member-pointer is left indeterminate** when creating a variable of type `Uppgift1`, and you generally ignored the "rule-of-three", which says you really have to define copy-ctor and copy-assignment in addition to the custom dtor.

Next, let's look at how the members pointe is deleted:

```
delete t;

```

As the type of `t` does not have a virtual dtor, it must point to an object of the fully-derived type the pointer declares.  

Unfortunately, you are setting a `Shouter` last, which is a derived class, and thus have UB.

You should take a look at smart-pointers, especially `std::unique_ptr`, and for some occasions `std::shared_ptr`.

Before:

```

uppg1.SaySomething();
uppg1.SetSoundProducer(new Shouter);

```

You make a call on set twice but only one can be held.


In addition to all that's been said, you're calling `_CrtDumpMemoryLeaks();` before `uppg1` goes out of scope and has its destructor called. Put the stuff before it in a `{}` block, or you'll see memory leaks even when the code is fixed.
