## Question

part of my application is a daemon that runs in the background and regularly collects data and writes it to the sqlite3 database.
Sadly the process seems to leak a bit of memory every "sync" (getting data and writing it to the db).
What I basically do is: create a new thread where the whole sync process takes place, create some empty "Gee.LinkedList", pass them to some functions to fill them, then pass them to other functions to write them to the db. I am not aware of any leftover references to the LinkedList's after the process is done. So theoretically the data should be freed. I checked the reference count of the object shortly before running out of scope and it was 1. I there a way to check if a object has been successfully freed?
I tried using valgrind to see if I can detect the problem in my code.
