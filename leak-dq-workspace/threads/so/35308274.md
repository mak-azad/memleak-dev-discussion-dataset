## Answer 35309860 [ACCEPTED]

responder · Prof. Falken · 2016-02-10T08:13:18Z · score 2 · https://stackoverflow.com/a/35309860

Unfortunately, the libraries that `printf` uses, do not always behave in an ideal way. Valgrind will notice all errors - not only the ones you made, but every error made in the standard C library implementation on OSX, for instance.

Some of those "errors" may be actual bugs (which is pretty rare), others are likely little shortcuts the library developers took, which may not look completely correct to Valgrind. One such thing is to rely on the *operating system* to clear and free all left over memory when a program exits - when in a pedantic world, the program should free all of its memory before exit. However, this stopped being strictly necessary somewhere around the days of [DOS](http://www.drdobbs.com/architecture-and-design/mapping-dos-memory-allocation/184408026) and [AmigaOS](http://wiki.amigaos.net/wiki/Obsolete_Exec_Memory_Allocation).

I am not saying this is necessarily what you are seeing in that error, but that you need to be mindful of what Valgrind says.

To use Valgrind in practice, you may want a suppression file, which removes error messages related to system libraries. Here is a somewhat recent (January 2015) [blog post about this issue](http://ranf.tl/2014/11/28/valgrind-on-mac-os-x-10-10-yosemite/) which came about exactly because of "learning C the hard way" on OSX.
