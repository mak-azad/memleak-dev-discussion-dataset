## Answer 3788037

responder · sth · 2010-09-24T14:28:11Z · score 12 · https://stackoverflow.com/a/3788037

You are only allowed to `delete` those objects that have been allocated with `new`. If you try to call `delete` on a pointer pointing to an object on the stack, you will probably crash your program.

## Answer 3788165

responder · Roger Pate · 2010-09-24T14:43:24Z · score 0 · https://stackoverflow.com/a/3788165

If you need to know that ownership is transferred, then don't use raw pointers.  Use smart pointers, such as std::auto_ptr (Boost and C++0x have many more) which make the transfer of ownership explicit and additionally convey how to destroy the objects (for auto_ptr this means delete):

```
struct Example {
  Example(std::auto_ptr<T> parent, std::auto_ptr<TObject> left,
          std::auto_ptr<T> right)
  : _parent (parent), _left (left), _right (right)
  {}

private:
  std::auto_ptr<T> _parent, _left, _right;
};

```

You could still store raw pointers, if you really insist, by using auto_ptr's release method and writing a copy ctor, destructor, and assignment operator for Example (the Rule of Three).

## Comment on question 3788005 4015324

responder · David Rodríguez - dribeas · 2010-09-24T18:00:21Z · score 0 · https://stackoverflow.com/questions/3788005/#comment4015324_3788005

@There is nothing we can do: On the particular issue of *why would it be bad/illegal C++ to delete manually an object from an std::stack?* The answer is that you are not responsible for the management of that memory, and as such you should not delete. It will cause Undefined Behavior as the container will try to free the resource itself (double delete) and because in most cases the pointer you might get is not a pointer returned from a call to `new` (the stored object can either be a subelement of an array or a subobject in a node, depending on the underlying container.
