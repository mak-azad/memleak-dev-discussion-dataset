## Answer 44424843 [ACCEPTED]

responder · user2100815 · 2017-06-08T00:35:42Z · score 2 · https://stackoverflow.com/a/44424843

It's generally impossible to check if a pointer is "valid", given only the pointer. Certainly, calling delete on an "invalid" pointer will not throw an exception, except perhaps via undefined behaviour. 

Basically, your code needs to explicitly track whether a pointer is "valid" or not. Or better use smart pointers, such as std::unique_ptr.

responder · user4581301 · 2017-06-08T04:32:58Z · score 0 · https://stackoverflow.com/questions/44424820/#comment75851339_44424843

@michaeleric yes, but that requires something to have been thrown. `free` is a good ol' C function and C knows not what an exception is and thus cannot throw an exception. You also cannot catch signals such as segfaults and floating point exceptions (because it turns out FPE isn't an exception in the C++ sense), asserts, aborts, and many other forms of program-crashing ninjitsu. Most of the time you don't want to intercept, handle them, and continue because they mean your program is utterly hosed and should be allowed to die peacefully.

responder · user207421 · 2017-06-08T09:34:56Z · score 0 · https://stackoverflow.com/questions/44424820/#comment75861373_44424843

@michaeleric The point is that there is no guarantee that undefined behaviour will throw an exception in the first place, so you can write whatever code you like to cope with undefined behaviour but there is nothing defined that says your code will ever be invoked. The solution is not to write more code, it is to fix the code that engages in undefined behaviour in the first place.
