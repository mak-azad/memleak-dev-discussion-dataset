## Answer 46837516

responder · Barmar · 2017-10-19T19:30:55Z · score 1 · https://stackoverflow.com/a/46837516

You can only call `free(ptr)` if the value of `ptr` was returned from `malloc()` or `realloc()`. Your code later has:

```
fecha = strtok(fecha, "/");

```

So when you get to the end of the function, `fecha` no longer contains the pointer that it originally contained when you did:

```
fecha = malloc(1000 * sizeof(char));

```

You should use a different variable in the loop so that you don't lose the original `fecha` pointer.

You have the same problem with:

```
fechaVariable = strtok(fechaVariable,"/");

```

so use a different variable here as well.

Actually, there's no good reason to use dynamic allocation for these variables at all. Just declare:

```
char fecha[1000], fechaVariable[1000], lluvia[1000];

```

Then use different variables with `strtok`, since you can't assign to array variables.

```
char *fecha_slash = strtok(fecha, "/");
char *fechaVariable_slash = strtok(fechaVariable, "/");

```

responder · Richard Chambers · 2017-10-19T20:15:48Z · score 0 · https://stackoverflow.com/questions/46836994/#comment80624042_46836994

I prefer using `strncpy()` and `strncat()` which each require a maximum number of characters to copy or concatenate rather than the `strcpy()` and `strcat()` functions just in case there is a missing zero terminator in the string that is being copied from. The idea is to prevent buffer overflow problems by copying too much. Then I put a zero terminator in the last `char` array element to make sure there is always a zero string terminator in the new string. So `char xArray[100];` I would use `strcpy (xArray, aszSource, 100 - 1); xArray[100 - 1] = 0;`

You also have a problem with the `memset(lluvia,'\0',sizeof(lluvia));` because the size of `lluvia` is the size of a `char *` pointer, 4 bytes on a 32 bit machine. You need to instead specify something like `1000 * sizeof(char)`.
