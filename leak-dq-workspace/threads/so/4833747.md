## Question

Below is the pattern of new/delete operators in my program. Valgrind says that memory is "definitely lost". I couldn't quite get where the leak is. Is there something wrong with my usage of new/delete operators.   

```
 class Generic
 {
        GenericInterface *gInterface; //GenericInterface is abstract class

        public:
           Generic ()
           {
                gInterface = NULL;
           }
           ~Generic ()
           {
               delete gInterface;
           }
           void Create()
           {
           gInterface = new Specific();
           }
    };

    class Specific : public GenericInterface
    {
       MyClass* _myClass; 

    public:
      Specific()
      {
         _myClass = new MyClass;
      }

      ~Specific()
      {
         delete _myClass; 
      }

    };

    int main()
    {
       Generic g;
       g.Create();
    }

```

valgrind says that memory is lost.

```

```

## Answer 4833786 [ACCEPTED]

responder · James McNellis · 2011-01-28T22:44:13Z · score 11 · https://stackoverflow.com/a/4833786

You are not following the [rule of three](https://stackoverflow.com/questions/4172722/what-is-the-rule-of-three).  If your class manages resources that need to be cleaned up, you *must* declare a destructor, copy constructor, and copy assignment operator.  Neither of your classes has a copy constructor or a copy assignment operator.

Really, you should almost certainly just be using a smart pointer like `unique_ptr` from C++0x; `shared_ptr` from Boost, C++ TR1, and C++0x; or `scoped_ptr` from Boost.

The likely issue causing this specific problem is that you have forgotten to make the base-class `GenericInterface` destructor `virtual`, so the wrong destructor is being called and the `MyClass` object that you dynamically create in `Specific` is never destroyed. 

`delete`ing an object via a pointer to one of its base classes results in undefined behavior if the base class destructor is not declared `virtual` (that means bad things will happen, ranging from memory leaks to crashes).
