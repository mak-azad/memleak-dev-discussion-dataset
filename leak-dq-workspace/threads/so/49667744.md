    this->size = 0;
    this->capacity = capacity;
    this->elems = new T[capacity];

    this->size = v.size;
    this->capacity = v.capacity;

    for (int i = 0; i < this->size; i++)

{
    delete[] this->elems;

## Answer 49670752

responder · Red.Wave · 2018-04-05T11:01:15Z · score 1 · https://stackoverflow.com/a/49670752

Why don't you just use `std::vector`?
Dynamic allocation is really tricky; you gotta follow the recommend but undocumented pattern for RAII with several requirements: copy/move constructor, assignment operator, swap function, destructor. You'd better stick to the `std::vector`, unless - of course - it is banned.

## Answer 49681625

responder · Red.Wave · 2018-04-05T21:14:12Z · score 0 · https://stackoverflow.com/a/49681625

So take the long way and define all special functions - and a swap function to be used in some of those in order to refactor the code. If either one of those functions is left default, sooner or later someway or other you will end up with dangling pointers, double deleting, use of deleted pointers and hopefully an early crash to finish the nightmare.
All special members MUST be properly defined. 
The "big 5" (formerly "big 3") is the idiomatic way of implementing RAII. You gotta define destructor copy-constructor and copy-assignment(plus the move-counterparts). I wish you could at least use unique_ptr.
