## Answer 58518031 [ACCEPTED]

responder · Lukas · 2019-10-23T07:50:16Z · score 1 · https://stackoverflow.com/a/58518031

This is better reported on the [official forum](https://en.sfml-dev.org/forums/index.php#c3), as mostly the maintainers will be able to tell you, whether it's an actual leak or just a false-positive.

Looking at [the source](https://github.com/SFML/SFML/blob/master/src/SFML/Window/OSX/VideoModeImpl.cpp#L80), I don't really see how anything is leaked and it seems more like macOS itself would leak something. Only thing I could vaguely think of is that the returned value from `CGMainDisplayID` also needs to be releases again.

Note: If you make use of the new C++ standards, especially smart pointers and avoid doing manual memory management, there's often little need to track memory leaks regularly, as they tend to not happen anymore (i.e. memory automatically freed once the smart pointer runs out of scope).
