{
    extern char **environ;
    unsigned int i;

    for (i = 0; environ[i]; i++)

A child process cannot change the environment of its parent process. Even if your `set` command works, any changes it makes will be lost when it exits, and `getenv` will only see the environment inherited from the calling shell.

## Answer 72374081

responder · Blabbo the Verbose · 2022-05-25T08:12:08Z · score 1 · https://stackoverflow.com/a/72374081

1. 

Each string in the `environ` array has, and must have, format *name*=*value*.  For robustness, you can also support format *name*.  The *name* part may not contain `'='`.

Your `_getenv()` only matches a *prefix* of *name*, since it does not verify the name is immediately followed by an end of string nul character (`\0`) or a `=` indicating that the value follows.  It also returns the pair, and not just the value.  You need to fix these.

1. 

Each process can only modify its own environment.

For testing, you can have your `main()` do some `_getenv()` and `_setenv()` calls to verify they work –– I'd personally use command-line parameters for this –– and then just execute `/usr/bin/env`, which by default prints the environment, for example by `execl("/usr/bin/env", "env", NULL);`.

The first parameter to [execl()](https://www.man7.org/linux/man-pages/man3/exec.3.html) is the path to the executable, the second parameter is the self-name the executable sees (`argv[0]`).  Any following parameters are command-line argument strings, followed by a single `NULL`.  If successful, the call will never return; the process is replaced by the `env` program.  It is common, however, to put something like `fprintf(stderr, "Cannot execute /usr/bin/env: %s.\n", strerror(errno)); exit(EXIT_FAILURE);` after the exec, so that if env cannot be executed, the user will see an error message instead of silence.

If you want to use a shell command instead, you can do e.g. `execl("/bin/sh", "sh", "-c", "command or commands to run in the shell", NULL);` instead.  To see only lowercase environment variables (because the standard ones are all in uppercase), you could use `execl("/bin/sh", "sh", "-c", "env | grep -e '^[a-z]'", NULL);`.

1. 

`environ` is an array of pointers terminated by a NULL pointer.  Each pointer points to a separate string, either static/constant, or dynamically allocated.  (Unfortunately, we don't know which.)

To add a new pointer to the array, you do not need to create copies of each string in the array, you only need to create a new array, copy the pointers over, and add the new (dynamically allocated string) pointer and a NULL pointer at the end of the array.  In other words, you only grow the array of pointers (and thus only need the existing number of entries).

If you use `realloc()` to grow the `environ` array, you don't even need to copy the pointers over.  Just remember that `realloc()` may return either the same or a different pointer for the resized `environ` array.

Because we don't know whether each pointer in the `environ` array is dynamically allocated or not, `unsetenv()` basically has to leak memory, and not call `free()` on the discarded environ pointer.

[putenv()](https://www.man7.org/linux/man-pages/man3/putenv.3.html) adds the specified string as-is to the `environ` array, removing any previous entry with the same name part.  In Linux (using GNU C library), if the string does not contain a `=` character, it is not added, but any previous entry with the same name part is removed.

1. 

In Linux, the [/proc/*PID*/environ](https://man7.org/linux/man-pages/man5/proc.5.html) pseudo-file contains the initial environment a process was started with.  (It looks and acts like a file, but is really something that the kernel generates whenever it is accessed, not something that is stored in memory or in any storage.)

It is quite possible, but not generally necessary, to keep this up to date whenever modified via `getenv()`/`setenv()`/`putenv()`/`unsetenv()`, and even avoid leaking memory (unless the user does so via `putenv()` themselves).

This is done by using a contiguous dynamically allocated stack-like area (anonymous memory map with `MAP_STACK` and `MAP_GROWSDOWN` flags) as a char buffer, to keep all the strings specified in the `environ` array, with each string separated by a single `\0`.  When the area is moved or resized, `PR_SET_MM_ENV_START` and `PR_SET_MM_ENV_END` [prctl()](https://man7.org/linux/man-pages/man2/prctl.2.html)s are used to tell the kernel where it is and how large it is.  (Those calls may fail if you try to use a normal malloc()'d memory region for it.)

The kernel isn't at all interested in the `environ` array of pointers; that's just how environment variables are implemented in the standard C library.

For process ID *PID*, you can run `cat /proc/PID/environ | tr '\0' '\n'` to see the initial contents of the environment area when that process started.  (This is also the reason we do not normally pass 'secrets' in environment variables or in command-line parameters (`/proc/PID/cmdline`), and use pipes or Unix domain sockets instead.)
