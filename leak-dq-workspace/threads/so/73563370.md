## Question

I am writing a program for adding points to a polygon class here is the code below. I am getting memory leaks and am completely lost. Many thanks!

UPDATE: maybe is there an alternative to memcpy??

```
#include <iostream>
#include <cstring>
#include <cstdint>

struct Coordinate {
    int x, y;

    Coordinate () : x(), y() {}
    Coordinate (int _x, int _y) : x(_x), y(_y) {}
};

class Polygon {
    int points;
    Coordinate** coordinates;

public:

    Polygon (int _points) {
        points = _points;
        coordinates = new Coordinate*[points+1];
    }

    ~Polygon () {

        for (int i = 0; i <=points; i++){
            delete coordinates[i];
        }
        delete [] coordinates;

    }

    void putPoint (Coordinate ** pts) {
        for (int i = 0; i < points; i++) {
            memcpy(&coordinates[i], &pts[i%points], sizeof(coordinates[i]));
        }
    }

};

int main () {

    Coordinate q1 = {0,0};
    Coordinate q2 = {0,2};
    Coordinate q3 = {2,2};
    Coordinate q4 = {2,0};

    Coordinate* quadPts[4] = {&q1, &q2, &q3, &q4};
    Polygon * quad = new Polygon(4);

    quad->putPoint(quadPts);
}

```

## Answer 73576305

responder · Etienne de Martel · 2022-09-01T23:23:00Z · score 0 · https://stackoverflow.com/a/73576305

Okay, so, your `Coordinate` struct does not need to be dynamically allocated like that. It's small, trivially copyable, has value semantics, and has no virtual members. You gain nothing by using pointers for those.

Second up, dynamic arrays are a pain to use. You should *always* use a container instead, preferably `std::vector` since it has the same general characteristics.

Finally, while `memcpy` works fine here for `Coordinate` because it's trivially copyable, it's a bad idea in C++ to use it to copy objects, because the moment you use it for something a bit more complicated than that, you end up with undefined behaviour. Really, `memcpy` should only be used for byte buffers.

Putting all of that together, here's a simplified version:

```
#include <vector>

struct Coordinate {
    int x, y;

    Coordinate () : x(), y() {}
    Coordinate (int _x, int _y) : x(_x), y(_y) {}
};

int main () {    
    Coordinate q1 = {0,0};
    Coordinate q2 = {0,2};
    Coordinate q3 = {2,2};
    Coordinate q4 = {2,0};

    std::vector<Coordinate> quad = { q1, q2, q3, q4 };
}

```

That's it. Of course, it's not exactly the same: I got rid of `Polygon` and used a vector directly, because it was unnecessary with your current use case. Feel free to wrap it into a class, if you want.

The point here is that most of your code was basically recreating standard library facilities, but poorly. Once you start thinking about what's already available, a lot of the complexity disappears.
