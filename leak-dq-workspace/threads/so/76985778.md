## Answer 76985799 [ACCEPTED]

responder · Ahmed AEK · 2023-08-27T05:17:37Z · score 7 · https://stackoverflow.com/a/76985799

```
vector<int>& f() {
    vector<int> a = *new vector<int>{15, 15, 16};
    return a;
}

```

This is calling the copy constructor of `a` and passing the heap allocated object to it. `a` is not created on the heap. It is destroyed when `f()` exits, leaving the returned reference dangling, and the heap allocated vector leaked after the constructor.

Use a reference instead of a second object. Just bind the already created vector on the heap to the reference that gets returned.

```
vector<int>& f() {
    vector<int>& a = *new vector<int>{15, 15, 16};
    return a;
}

```

While this may work, **This is bad design**

A reference is a non-owning construct, it doesn't manage the object's lifetime, while your code expects the caller to `delete` the object, this is a memory leak waiting to happen.

---

The proper way to make this code work is to simply return the vector from your function and let the compiler move it:

```
vector<int> f() {
    vector<int> a{15, 15, 16};
    return a;
}
...
vector<int> b = f();

```

## Comment on question 76985778 135716317

responder · Nathan Pierson · 2023-08-27T07:30:58Z · score 1 · https://stackoverflow.com/questions/76985778/#comment135716317_76985778

Actually, your understanding of how `new` and `delete` pair together isn't quite right. Your `delete` applies to a different `vector` than the one you originally `new`'d. When you wrote `new vector<int>{15, 15, 16}`, the `vector` that was created here was *copied* to initialize `a`, but a pointer to it was never stored anywhere in the program. Then `a` was destroyed at the end of `f()` because it had automatic storage duration, but because `b` is a dangling reference to it you try to `delete` it again. But you never tried to `delete` the original `vector`, and in fact cannot.
