*I know by several sources that the result should show shared memory to be faster.*  What OS is being used in those sources?  What specific version of that OS?  What hardware?  How many CPUs might be critical.  **When** were those sources written?  Spectre and Meltdown mitigations significantly increased the cost of system calls in Linux and your pipe implementation doesn't need to use semaphores, which require more system calls to pass data.  See [**Disable Spectre and Meltdown mitigations**](https://unix.stackexchange.com/questions/554908/disable-spectre-and-meltdown-mitigations)

The `sem_wait()` and `sem_post()` operations are not particularly cheap, especially when the semaphore is shared between processes.  With the pipe, the kernel is doing the synchronization for you.

Aside from `sem_wait/sem_post` being slow, you have only *one* shared memory buffer. I recommend a [reusable] pool of such buffers.
