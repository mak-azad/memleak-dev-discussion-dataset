## Question

I write in C and compiling to webassembly like this:

```
clang --target=wasm32 -O3 -mbulk-memory -c source1.c -o 1.o
clang --target=wasm32 -O3 -mbulk-memory -c source2.c -o 2.o
wasm-ld 1.o 2.o --export-all --strip-all --no-entry -o myprogram.wasm

```

(spoiler: this works (somehow))

The goal is to avoid linking with libc-like libraries and avoid linking with... anything, because want by wasm binary be several KB in size, also dont need "normal" malloc()/free(), because dont want to free anything (so why keeping sizes of chunks?). My memory management too simple or my own super-simple arena-allocator will be implemented later: with probability P=0.999 I will use very simple data structures working in fixed memory arena, using it as a couple of fixed-sized buffers or something like this. So, when I need a buffer in WebAssembly program, I do this in C code in global "namespace":

```
int buffer[1024 * 1024 * 8] = {0};
// Done. Memory is alocated "by compiler".

void function_do_something() {
   // the "buffer" is my arena and i know where everything is in that buffer
   int *foo = &buffer[OFFSET_TO_FOO];
   int *bar = &buffer[OFFSET_TO_BAR];

   // example of my average data manipulation code
   for (int i = 0; i < 1024; ++i) {
     foo[i] = bar[i] * 123;
   }
}

```

The only allocation I do is declaring the `int buffer[...];` with fixed size.

Example of how I access the memory from JS:

```
// the "wasm_instance" is the product of my `WebAssembly.instantiate()` call somewhere before this...

// here I access some data in webassembly instance:
var data = new Uint8ClampedArray(wasm_instance.exports.memory.buffer, offset, len);

```

The questions:

1. What is the correct way to guarantee that my `...exports.memory.buffer` has enough size? Who guarantees the `1024 * 1024 * 8 * sizeof(int)` will be allocated?

1. How to increase the memory awailable for the webassembly instance from the C or JS code? I would like to have an arena of empty size in C code (`int *arena = 0`) and increase the size of that arena when i want. Is there some wasm32-platform intrinsics in C code known by clang that does the job? Also good solution would be: C code **asks** JS to do the **allocation/resize** and then JS reports to C code the allocation is done. Any ideas here?
