## Question

In my JNI program, I use

```
new
delete
env->NewGlobalRef
env->DeleteGlobalRef
jvm->AttachCurrentThread
jvm->DetachCurrentThread

```

What is a good way to check for memory leaks rigorously?

## Answer 9099177 [ACCEPTED]

responder · Mankarse · 2012-02-01T16:11:09Z · score 3 · https://stackoverflow.com/a/9099177

Make sure that every `new`, `env->NewGlobalRef` and `jvm->AttachCurrentThread` is in the constructor of an object which calls the matching deallocation function in its destructor.

This is a technique called [RAII](http://en.wikipedia.org/wiki/RAII), which is vital to writing any correct program in C++.

## Answer 9100268

responder · Ortwin Angermeier · 2012-02-01T17:21:07Z · score 0 · https://stackoverflow.com/a/9100268

- First try to use [smart pointers](http://www.boost.org/doc/libs/1_48_0/libs/smart_ptr/smart_ptr.htm). 

- As Mankarse pointed out, try to use the RAII idiom whenever possible to create and delete your global references.

- Use as less global rferences as possible

- Free local references when constructing them in a loop

Take a look at [here](http://java.sun.com/docs/books/jni/html/refs.html) for managing references.

Do you already know that your native code is leaking memory?
